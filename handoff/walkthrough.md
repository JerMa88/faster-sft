# AA-SFT Experiment Walkthrough

> **Status (2026-08-07):** Experiments complete. All 28 AA-SFT runs evaluated. Paper updated to V1 AA-SFT as primary method.

---

## Overview

This project investigates the **Knowing-Using Gap (KUG)** in LLMs: models memorise injected facts ($A_\text{mem}$ high) but fail to use them in multi-hop reasoning ($A_\text{gen}$ low). We propose **Alignment-Aware SFT (AA-SFT)** — four auxiliary loss variants that align hidden-state representations of the same fact across a memorisation prompt and a generalisation prompt, closing ~32–35% of the oracle headroom at zero inference cost.

---

## Completed Pipeline

### Phase 1: Data Preparation
- **STaRK-PRIME** and **STaRK-MAG** datasets processed to `data/processed/stark_{prime,mag}_qa.jsonl` (1,000 pairs each)
- Paired $(P_\text{mem}, P_\text{gen})$ format with entity span annotations

### Phase 2: Layer Profiling + Probe Pre-training
- Per-model layer profiles in `data/processed/layer_profile_<model>.json`
- Pre-trained frozen probes in `data/processed/probe_phi_<model>.pt`
- Run via `scripts/training/run_profiling.py` and `scripts/training/pretrain_probe.py`

### Phase 3: Training (SLURM)
- **4 models** × **2 datasets** × **5 loss variants** (baseline + 4 AA-SFT) = 40 runs intended
- Antares-1B and Nanbeige4.2-3B excluded (CUDA kernel deadlocks on A100)
- **28 runs complete** in `outputs/runs/`
- Training script: `scripts/training/train_sft.py`
- Launch: `slurm_jobs/run_alignment_sweep.sh <model_key>`
- Hyperparams: LoRA r=16 α=32, AdamW lr=2e-4, 50 epochs, λ=0.1, warmup K=3, seed 42

### Phase 4: Evaluation
- Evaluator: `scripts/evaluation/evaluate_v1_runs.py`
- **Metric: Relaxed EM** (gold answer as substring of model output, case-insensitive)
- Results in `eval_results.json` per checkpoint; A_mem and A_gen curves at epochs [1,3,5,10,15,20,30,50]

### Phase 5: Analysis + Paper
- Figures generated by `scripts/analysis/generate_paper_figures.py` → `paper/figures/`
- Paper: `paper/main.tex` (ACL 2026 Long Paper format)
- Committed at `090e8f0`

## V1 vs V2 Finding

A V2 training sweep was attempted (`slurm_jobs/run_alignment_sweep.sh` with `stark_prime_qa_v2.jsonl` + BridgeAlign extra loss), saved to `outputs/runs_v2/`. V2 only beat the baseline on 2/7 pairs.

**Root cause:** The V2 BridgeAlign auxiliary term suppresses memorisation (A_mem 30% lower throughout training), which proportionally limits generalisation. V1's simpler loss lets the model memorise first, then alignment routing kicks in effectively. V2 data and results are retained in `outputs/runs_v2/` for reference.
